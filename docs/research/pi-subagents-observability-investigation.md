# pi-subagents observability: architecture investigation

**Evidence pins (2026-09-24):** Inspector checkout `63374860c0c7145f56cb719bf322d5cebca51b9a`; producer `pi-subagents@0.71.0`, Git HEAD [`6f16d586bef814d74b3a2683cf297450ebfccb09`](https://github.com/nicobailon/pi-subagents/tree/6f16d586bef814d74b3a2683cf297450ebfccb09); locally installed package also reports `0.71.0`. `P:` below means a path in that pinned producer checkout; `I:` means a path in the pinned Inspector checkout. Function names and path references identify the precise evidence. Earlier Inspector research pins `0.70.1` and historical `0.59.0`; do not conflate these with this inspection (`I:docs/research/pi-ecosystem.md`, Item 13 audit). This is a read-only design investigation, not a tested implementation or a claim that a particular private session has six attributable records.

## 1. Executive conclusion

**Yes, ownership is duplicated, but RPC is not a replacement for the persisted adapter today.** The producer now owns async status reconciliation, receipt/metadata-backed cost recovery, restart handling, process-terminal proof and nested/workflow state (`P:src/runs/background/async-status.ts:listAsyncRuns`, `P:src/slash/subagent-cost.ts:collectSubagentCost`, `P:src/runs/background/async-job-tracker.ts:restoreActiveJobs`, `P:src/runs/background/process-terminal.ts:finalizeProcessTerminal`). Inspector independently reconstructs *persisted Pi tool-result* runs and must continue to do so for history (`I:src/integrations/subagents.ts:collectRuns`, `I:src/ui/load-history.ts:scanDiscoveredSession`). These are overlapping interpretations, not interchangeable ledgers.

**Can we safely delete roughly half of `integrations/subagents.ts` now? No.** It has **1,131 lines**. RPC `status` has no structured, exhaustive completed-child ledger; `asyncSnapshot` has a bounded 20-root window and lacks usage/model; Fleet is active/display-only and deliberately hides IDs; RPC `cost` walks the *current branch*, omits zero-usage children, has incomplete async coverage, and fills absent usage components with zero. Replacing durable `results[]`/`completions[]` parsing with these would regress history, deterministic attribution, and unavailable-versus-zero semantics (`P:src/extension/rpc.ts:handleRequest`, `P:src/runs/shared/async-status-projection.ts:projectAsyncStatusSnapshot`, `P:src/slash/subagent-cost.ts:collectSubagentCost,usageFromValue,addChild`). A safe near-term simplification is perhaps **100–250 lines (~9–22%)**, primarily centralizing joins, redundant bounds and repeated projection, *after tests*; not a guaranteed deletion. **Approximately 450–600 lines (~40–53%) are conditionally replaceable** only if pi-subagents publishes an exhaustive, session-linked, versioned **durable per-child fact contract** with stable cross-surface identities, field-presence semantics and proven retention. That is an upstream-contract dependency, not an implementation estimate for the next PR. Some present duplicate discovery of workflow results should be corrected, not merely deleted.

**Completed-run RPC answer:** It can return *some* completed runs for a short time through `status.asyncSnapshot` (recent in-memory fleet, max 20 terminal jobs; 10-second active-job retention by default) or `cost.children` *when the child is on the current Pi branch or a referenced workflow receipt plus metadata is readable*. Untargeted executor status lists queued/running only; targeted status can read/reconcile a retained `status.json` or foreground-history file but returns primarily **text** and empty `details.results`, not a safe complete structured AgentRun (`P:src/runs/background/run-status.ts:inspectSubagentStatus`, `P:src/runs/foreground/foreground-history.ts:restoreForegroundRunHistory`, `P:src/runs/background/async-job-tracker.ts:rememberFleetJob,scheduleCleanup,restoreActiveJobs`). After restart, active async jobs are restored, **not completed jobs**. RPC does not reconstruct all completed metrics from a permanent producer ledger. Thus live RPC is not historical authority.

**Persisted reading remains necessary.** Keep parent Pi JSONL publications. Follow only validated, session-owned `asyncDir`/archive references *published in a supported persisted result*; read version-validated `status.json`/proof only where an approved lifecycle contract and retention model suffice. Do not scan producer temp roots, treat `events.jsonl`, replay records or result files as a permanent ledger, or replay child session content. A launch with `mode:single`, `asyncId`/`runId`, `results:[]` can prove existence of an async *run* even before metrics arrive; a parallel/workflow root cannot prove every child from an empty results array. Persisted terminal coverage for an unwaited async child **after cleanup is not guaranteed in 0.71.0**. To promise indefinite detailed parity, seek an upstream session-persisted compact completion publication or explicitly design a bounded, durable, session-owned sanitized Inspector projection with a new retention decision. The latter must not silently expire with the 14-day detailed WAL (`I:docs/architecture/adr/0012-hot-retention.md`). Until then disclose coverage.

**WebSocket choice:** transmit `{reportChanged, revision, scope}` invalidation only; HTTP refetch returns the same reconciled canonical report as JSON/TUI/static. Events trigger rebuilds, never become source facts.

## 2. Current Inspector architecture

```
 Pi persisted session JSONL -- parseSessionJsonl --> buildCanonicalSession(scope/marker)
         |                                           |
         +--> selected scoped entries --> subagentsIntegration.canonical
               --> readSubagentEvidenceWithArchives
                   call/result join -> results/completions/workflow parsing
                   -> opaque IDs, same-surface merge, archive verdict
                        |                       |
                        +--> attachSubagentEvidence -> canonical agents + child ledger
                                  -> toSessionReport -> UI model / JSON / static / TUI
 Inspector WAL/checkpoint/inventory -> L0 provider -----------^

 current: loadCurrentSessionReport(scope=active|tree, provider from index.ts)
 history: discoverHistory(manifests) -> loadHistorySessionReport(tree)
          -> readHistorySessionEvidence -> same canonical/report path
 global: history scan/dated aggregate; localhost UI bundle shares these loaders.
```

Exact seams: `I:src/ui/load-current.ts:loadCurrentSessionReport`, `I:src/ui/load-history.ts:scanDiscoveredSession,loadHistorySessionReport`, `I:src/index.ts:readHistorySessionEvidence,readSubagentContribution`, `I:src/integrations/adapters/subagents.ts:subagentsIntegration`, `I:src/integrations/catalog.ts:defineIntegration`, `I:src/integrations/contract.ts`, `I:src/integrations/contributions.ts:readCanonicalContributions`, `I:src/core/canonical.ts:buildCanonicalSession,attachSubagentEvidence`, `I:src/core/reports.ts:toSessionReport,canonicalReportEvidence,projectAgent`, `I:src/ui/bundle.ts`, `I:src/ui/ui-projection.ts:agentParentVerdicts`, `I:src/ui/agent-tree.ts`. `I:src/integrations/subagent-archive.ts:readPublishedArchiveState` is a bounded no-symlink version/identity *presence* check, not a payload reader. `I:src/core/events.ts:AgentRun,AgentRunUsage,AgentRunEffortCoverage` contains no `executionKind`/`requestedModel`; `AgentRun.parentId` is optional. `I:src/core/reports.ts:projectAgent` rechecks fields/coverage and currently drops even a validated new field unless updated. Integration presence uses native tool names, not installed-package certainty.

Important observed gap: `SUBAGENT_TOOL_NAMES` in `I:src/integrations/subagents.ts` lists `subagent`, **`subagent_wait`**, `subagent_supervisor`, while current producer registers **`bg_wait`** (`P:src/runs/background/wait-tool.ts:registerWaitTool`), and producer cost explicitly accepts `bg_wait` (`P:src/slash/subagent-cost.ts:detailsFromSessionEntry`). Since Inspector admits publications only after a joined recognized call, genuine `bg_wait` completion details can be missed (`I:src/integrations/subagents.ts:deriveEvidence,collectCalls`). This is a concrete visibility candidate, **not proof** of the given session's missing two; verify sanitized Pi JSONL. Async launch with empty `results[]` is also currently skipped (`I:src/integrations/subagents.ts:collectRuns`; `P:src/runs/background/async-execution.ts` single/chain launch returns `details.asyncId,runId,asyncDir,results:[]`). Keep Session History token/cache regression separate; it concerns native report projection, not this integration.

Normative boundaries: `I:docs/specs/pi-session-inspector-v1.md` §10 currently permits tool-result discovery and published archive references, **not** general status-artifact ingestion or child session replay. `I:docs/architecture/adr/0007-subagent-rollup.md` bans guessed relationships/additive child usage; `0009-hybrid-integrations.md` establishes native-first; `0010-telemetry-protocol-v1.md` and `0011-local-only-privacy.md` constrain storage; `0016-evidence-foundation-and-canonical-session-model.md` makes L0 validation/L1 reconciliation/L2 presentation normative; `0019-integration-adapter-registry.md` defines registry ownership; `0021-agent-run-effort-and-coverage.md` limits current audited effort. **Any new direct status reader is an architecture boundary change: update spec + ADR in implementation PR.** Current `subagents.ts` merges source observations inside its adapter even though ADR 0016 describes L1 as owner of reconciliation; move multi-source merging to L1-compatible reconciliation, do not replicate it in L2.

## 3. Actual producer observability architecture

```
 in-process pi.events RPC (protocol v1)
  ping -> static capability advertisement + current session identity
  status untargeted -> if restored/current state ready: fleet + asyncSnapshot
                   -> else executor inspectSubagentStatus
                        -> indexed active status.json, or targeted retained status/result
      fleet <- foreground controls + async/fleet jobs (opaque display keys)
      asyncSnapshot <- current-session asyncJobs + recent fleetJobs
  cost -> collectSubagentCost(current sessionManager.getBranch())
          -> assistant/compaction usage (parent)
          -> subagent/bg_wait details.results / details.completions (children)
          -> referenced workflow receipt -> child artifact metadata (additional children)
          -> parent + childTotal (lower bound) = producer total

 detached runner -> status.json (lifecycle v3), events.jsonl, result file
 parent watcher -> completion replay v1/archive v1 -> delete delivered result file
 optional bg_wait -> details.completions[] in persisted parent Pi tool result
 reload -> active status/index restoration; foreground remembered history bounded
 later cleanup -> replay TTL; retention may remove eligible terminal async roots.
```

RPC `ping`, `status`, `cost` wiring: `P:src/extension/rpc.ts:pingData,canUseInMemoryStatus,handleRequest,registerSubagentRpcBridge`; protocol names in `P:docs/extension-api.md` “In-process event-bus RPC.” In-memory snapshot schema is `kind:"pi-subagents.async-status-snapshot",version:1`, caps defaults 20 runs, 8 children/node, depth 3, 32 KiB; it has identity/state/times/activity, **no exact cost, four-part usage, model, requestedModel or thinking** (`P:src/runs/shared/async-status-projection.ts:AsyncStatusSnapshotNode,projectAsyncStatusSnapshot`; `P:src/runs/background/async-status-snapshot.ts:asyncStatusSnapshotJobsForState`). Truncated node IDs are display strings: do not accept a truncated snapshot identity as a canonical join. Fleet v1 contains opaque **display** keys and active, bounded tokens; it cannot join to a persisted run (`P:src/extension/rpc.ts:buildFleetStatus`; `P:docs/extension-api.md` “Fleet status DTO”). Neither rendered `status.text` nor `/subagent-cost` output should be parsed.

`collectSubagentCost()` mechanics (`P:src/slash/subagent-cost.ts`): parent sums assistant and compaction usage from **current branch**. For each recognized `subagent`/`bg_wait` (also slash custom-message) tool result, it reads `details.results[]` and `details.completions[].results[]`; child dedup prefers `runId`, otherwise `sessionFile`, otherwise cannot dedup. It drops children with no nonzero usage, translates missing numeric fields to **zero**, and sums accepted child usage into `childTotal`. It collects workflow `runId`s in branch publications, reads `workflow-receipt.json` (`P:src/workflows/workflow-receipt.ts:readWorkflowReceipt`), resolves receipt child IDs/continuations to run IDs, then looks up per-child metadata under derived artifact directories. A receipt missing/invalid/non-terminal can omit children without increasing `unresolvedAsyncChildren`; missing metadata for an identified child increments it. `parent` is **producer interpretation of Pi assistant+compaction branch usage**, not Inspector's canonical native composition; `children` is a partial breakdown; `total=parent+childTotal` is a **separate producer combined accounting view**, not an Inspector session total. No per-component cost breakdown or reasoning tokens in `Usage` (`P:src/shared/types.ts:Usage`; `P:docs/extension-api.md:cost`). The producer's own unit tests prove result/bg_wait same-run dedup and receipt metadata lower-bound behavior (`P:test/unit/rpc.test.ts` “answers cost ... session branch”, “receipt-recovered ... unresolved lower bound”). **Do not copy zero-filled RPC fields into Inspector as observed zeros, or substitute producer `total` for native totals.** It is stronger for identified workflow-async metadata recovery, weaker for arbitrary children, missing-field evidence and tree/history scope. Foreground single/parallel and completed foreground require a retained branch result; async single/parallel require a retained completion result (or workflow receipt for identified workflow children); nested only if exact nested results/metadata are surfaced, not automatic recursion. An unwaited non-workflow async child does not magically appear in cost.

Runner writes initial and terminal status/result (`P:src/runs/background/async-execution.ts` initial `status.json` and async launch details; `P:src/runs/background/subagent-runner.ts:writeStatusPayloadNow`, final publication around terminal `resultPath`; `P:src/shared/utils.ts:readStatus`); indexed status discovery/reconciliation is producer-owned (`P:src/runs/background/async-status.ts:listAsyncRuns`, `P:src/runs/background/terminal-run-index.ts:readRecentTerminalRunIndex`). Reload restoration selects **queued/running only** (`P:src/runs/background/async-job-tracker.ts:restoreActiveJobs`; test `P:test/integration/async-job-tracker.test.ts` “restores only active async runs for current session”). `events.jsonl` includes child Pi event mirrors and arbitrary control/event content, hence is **unsafe raw ingestion** even though lifecycle boundary events are documented (`P:src/runs/background/subagent-runner.ts`; `P:docs/observability.md` “Child session events”). Nested sidecars/registry are merged by the producer status path (`P:src/runs/background/run-status.ts:inspectSubagentStatus`); do not reconstruct them from logs.

**Documentation qualification:** `P:docs/observability.md` correctly warns cost can undercount with missing receipts; `P:docs/extension-api.md` accurately describes status's fast path. Broad statements that `status.json` “powers status,” Fleet has “recent async children,” or cost “parent-plus-child accounting” **do not promise exhaustive completed structured rows after restart**. Code additionally restricts untargeted status to active states and restores only active jobs. `P:docs/observability.md` calls result/replay temporary; do not elevate either to permanent history. `P:docs/extension-api.md` lists capability `processTerminalProof` but does not provide a general per-run typed RPC proof method: targeted `debug.run` details contain proof when retained, while `subagent:process-terminal` is a live hint (`P:src/runs/background/run-status.ts:inspectSubagentStatus`, `P:src/runs/background/process-terminal.ts:finalizeProcessTerminal`).

## 4. Completed-run lifecycle

```
 launch -> running -> terminal -> watcher delivery -> replay/archive -> reload
   |         |            |              |                  |            |
 parent Pi launch   status.json/events   result.json       replay TTL    restore ACTIVE only
 details.asyncId    live memory       + status/proof     -> unlink result  + current-branch Pi
      ---------------------------------------------------------------> restart
 parent Pi JSONL, if written, remains; explicitly linked async artifacts may remain
      -> retention cleanup removes eligible roots -> historical launch/result only.
```

| Phase | What remains, and which source owns it |
|---|---|
| Foreground running | In-process foreground controls / Fleet; no completed parent Pi result yet. No restart guarantee (`P:src/extension/rpc.ts:buildFleetStatus`; `P:src/runs/background/run-status.ts:inspectSubagentStatus`). |
| Foreground completed | Parent Pi `subagent` `details.runId+results[].index` plus usage, model/thinking and sometimes `progressSummary`; bounded producer foreground-history remembers up to 50 for targeted text/revival, not a permanent structured RPC listing (`P:src/runs/foreground/foreground-history.ts:persistForegroundRunHistory,restoreForegroundRunHistory`; `P:src/shared/types.ts:SingleResult`). |
| Async running | Parent Pi launch result `asyncId/runId/asyncDir,results:[]`; durable `status.json` and `events.jsonl`; live `asyncSnapshot`/Fleet after tracking, with caps; session-scoped active restoration (`P:src/runs/background/async-execution.ts`; `P:src/runs/background/async-job-tracker.ts:restoreActiveJobs`). |
| Async terminal, not delivered | Terminal `status.json`, one-shot result, process-terminal sidecar; targetable status/reconciliation; in-memory snapshot only while remembered. Failure before result publication may leave only status/unknown proof (`P:src/runs/background/subagent-runner.ts`; `P:src/runs/background/process-terminal.ts:finalizeProcessTerminal`). |
| Completion delivered | Watcher writes `completion-replay/<runId>.json` and output archive (best effort), then deletes result. Custom completion message is **not** itself a Pi usage-bearing tool result. `bg_wait`/subscription can persist `details.completions[]` if invoked/delivered as a Pi tool result; otherwise parent Pi has at most launch details (`P:src/runs/background/result-watcher.ts:createResultWatcher`; `P:src/runs/background/completion-replay.ts:writeCompletionReplay`; `P:src/runs/background/wait-completions.ts:collectWaitCompletions`; `P:docs/observability.md` “Usage and cost accounting”). |
| Parent continues | Parent JSONL accumulates new entries; previous completed result persists if published. Cost sees only *current branch* and any referenced receipt/metadata. Untargeted RPC status not a history listing (`P:src/slash/subagent-cost.ts:collectSubagentCost`; `P:src/runs/background/run-status.ts:inspectSubagentStatus`). |
| Pi reload/restart | New producer process restores active async jobs from indexed status, not completed jobs. Rebuilt `cost` uses current branch Pi entries plus reachable receipts/metadata; targeted status may resolve retained terminal files. `pi.events` live hints are lost (`P:src/runs/background/async-job-tracker.ts:restoreActiveJobs`, tests at `P:test/integration/async-job-tracker.test.ts:1003`; `P:test/unit/rpc.test.ts:180,214`). |
| Inspector history later | Parent Pi JSONL and Inspector's own manifest/WAL/checkpoint remain (subject to their rules); externally linked async status/proof only until producer cleanup. History has no in-process RPC by default (`I:src/index.ts:readHistorySessionEvidence`; `I:src/ui/load-history.ts:scanDiscoveredSession`). |
| Cleanup | Replay expires on notification dedup TTL (bridge passes 10 min at `P:src/extension/index.ts:608`; `P:src/runs/background/completion-replay.ts:readCompletionReplay,cleanupCompletionReplay`). Producer async retention has 30-day cutoff, defers active, resumable, workflow/nested/referenced or unresolved runs; *eligible* terminal roots may be removed (`P:src/runs/background/async-retention.ts:ASYNC_RETENTION_DAYS,runSkipReason,cleanupAsyncRetention`; `P:test/unit/async-retention.test.ts` “deletes old proven-terminal runs”). Workflow temp artifact roots can expire at 24 h on startup (`P:docs/observability.md` “Workflow and debug artifacts”). No infinite persistence guarantee. |

## 5. Evidence-source matrix

|---|---|---|---|---|

## 7. Identity and dedup matrix

| Surface | Strongest exact internal identity | Can join? / exclusions |
|---|---|---|
| Foreground `details.results[]` | `(Pi sessionId, details.runId, result.index)`; when row has its own producer `runId`, validate semantics before replacing. | Exact within foreground publication/progress. `details.runId` alone is container, not child. `P:docs/extension-api.md` “Structured delegation progress”; `P:src/shared/types.ts:SingleResult`. |
| Foreground workflow child summary/result | `(sessionId, workflowRunId, workflowKey==childId)` plus validated child `runId` when present. | Producer 0.71.0 exact-key evidence (`P:src/runs/foreground/subagent-executor.ts:workflowDetailsResults`; `P:src/workflows/workflow-child-summary.ts:workflowChildSummary`; `I:docs/research/pi-ecosystem.md` 0.71.0 follow-up). Same child may have multiple result rows: ambiguous cardinality cannot be coerced into one child usage. |
| Persisted async launch / targeted status / restored run | `(sessionId, asyncId/runId)` with exact session-owned reference and non-truncated ID. | Top-level *run/container*, not automatically every parallel child. `P:src/runs/background/async-execution.ts`; `P:src/shared/types.ts:AsyncStatus`. |
| Async workflow step | `(sessionId, workflow root runId, workflowKey)` and, when explicitly present, step.child `runId`. | Child run ID bridges workflow receipt/status/result if verified; workflowKey is root-local, not global. `P:src/shared/types.ts:AsyncStatus`, `P:src/workflows/workflow-receipt.ts:readWorkflowReceipt`. |
| RPC `cost.children` | `runId` (else sessionFile fallback *inside producer*). | Only join validated exact `runId` and session ownership; **never** use unvalidated `sessionFile` path or `label/agent` as an Inspector key. Zero-usage children absent. |
| `bg_wait` `details.completions[]` | outer `(sessionId,completion.runId)`; child `runId` if supplied. | Outer identity may be same async launch. For parallel child without runId there is no safe row-level join; do not use array order or agent name. |
| Nested child registry / restored child | explicit nested `runId`, `parentRunId`/parent step identity, session-owned route where available. | No join by hierarchy display label, timestamp or host `childId` alone across separate roots (`P:src/runs/background/run-status.ts:inspectSubagentStatus`). |
| RPC Fleet | opaque display `key`. | **Never join** to raw run ID. |
| RPC `asyncSnapshot` | `runs[].id` async root, child node ID `workflowKey/runId/step:index` depending on node. | Only root with exact bounded validated ID and same session; child `step:index` only within verified root. Omission/truncation cannot become “complete.” |
| Process proof / archive / replay | exact `(sessionId,runId)` plus own `version` and referenced/validated path. | Same root only, never directly a child when proof is aggregate; replay has TTL. |

**Proposed canonical key:** private discriminated `sessionId + producer execution ID + child discriminator` (`runId` where producer guarantees child identity; otherwise `(containerRunId,index)` *only* for foreground guaranteed index; workflow `(rootRunId,workflowKey)` until an exact child-runId bridge is proven). Explicit alias table per supported producer contract joins observations; no broad “same string anywhere” equivalence. Public `subagent-<digest>` remains generated by `I:src/core/opaque-id.ts:canonicalOpaqueDigest`, with explicit identity domain; changing existing foreground digests needs migration note and fixture proof. Conflicting IDs **withhold** a join, do not mint two confident rows for one unknown child. Hashes conceal raw IDs from the public DTO but are *not* security secrets.

## 8. Field-level authority / reconciliation contract

Rule common to every row: L0 validates bounded allowed fields only; L1 reconciles only exact identities; latest **valid** observation may upgrade an absent field, never replace present trusted terminal evidence with stale running; conflicting equally strong stable identity/agent facts become unavailable + closed-code diagnostic. A source disappearing does not delete persisted observations. Missing metadata after artifact expiry lowers coverage, never inserts zeros. No raw path, error or task leaks.

| Field | Primary authority | Live enrichment / fallback / conflict |
|---|---|---|
| Identity, agent | Parent Pi foreground result or validated session-linked async launch + producer child ID; exact workflow summary/child result | RPC only on exact alias; conflicting child identity/agent withhold attribution; no name/order join. |
| `model`, `requestedModel`, `thinking` | Persisted result first, validated referenced terminal status if publication lacks field | Live status may fill provisional blank; persisted explicit value wins, differing resolved vs requested models are *not* a conflict. Do not treat Fleet goal as safe label. |
| Execution kind / topology | Parent Pi launch (`asyncId`, mode), foreground result; explicit workflow/nested/detach metadata | Live state may enrich but cannot rewrite an established persisted kind. Root `workflow` and child `nested` are topology, not replacements for foreground/async. Unknown stays unavailable. |
| Parent AgentRun / orchestration | Exact child-run/parent-run link, else exact container link | No parent ID means **unavailable** unless explicit producer proof of direct primary-session child; never derive from mere nesting in UI. |
| Status / failure | Persisted terminal result, or validated terminal status/proof if completion absent | Live `running` for provisional only. A persisted success does not trump later **explicit same-run** resumed/replaced terminal without versioned continuation semantics; conflicting terminal states -> unknown + diagnostic. Failure only closed enums/exit code/signal/output state, not `error` prose. |
| Duration / toolCalls / turns | Persisted `progressSummary` (foreground) or versioned per-step status when same child; no observed-at subtraction | Live activity numeric fields provisional if safely attributed; missing is unavailable. `usage.turns` separate from generations/`turnCount`. |
| Input/output/cache read/cache write; cost | Explicit per-child persisted result, then validated versioned per-child terminal metadata/status; inspect RPC cost for exact validated child only if **each component's presence** can be proven | RPC cost v1 zero-fills missing parts: **not suitable** to fill missing Inspector fields or certify a zero. If sources disagree on explicit numeric fact, retain primary, flag closed conflict; never add child usage to native total. No component cost/reasoning from RPC v1. |
| Archive availability | Published completion `archivePath` + version/ID/no-symlink validation (`I:src/integrations/subagent-archive.ts`) | Missing ref=unavailable; missing once referenced=missing; later removal can update presence but never erase a prior persisted completion fact. |
| Process terminal | Version-1 producer proof from validated session-owned sidecar; `observed` means runner close plus lease/tree checks | Event/RPC proof hints provisional; no inference from PID, `endedAt` or result. Unknown remains unknown; not status success. |

There are **three distinct accounting views**: (1) Inspector native Pi session `usageComposition` is billing/source authority (`I:src/core/reduce.ts:reduceEntries`; `I:src/core/canonical.ts:attachSubagentEvidence`), (2) `AgentRun.usage` is separate child breakdown, (3) producer RPC `total` is *parent+children* with lower-bound caveats and different branch semantics; if ever exposed, label explicitly “producer combined estimate,” with scope/completeness, not as native total. Prefer internal compatibility/corroboration initially; no new public total in first PR.

Existing parser dialect needs documented pin and fixtures because persisted entries lack their own producer version. Explicitly gate unsupported semantic changes (not `packageVersion >= X`); additive unknown fields ignored *only within supported version/dialect*. `npm run compat:pi-subagents` is useful as an **opt-in maintainer check**: load installed producer version/contract fixtures and run a read-only known-protocol handshake in a controlled fixture harness, compare sanitized schema/behavior, report unsupported changes without modifying files/session; do not ship a runtime version heuristic or make producer a dependency. Fixture proposal: `tests/fixtures/pi-subagents/rpc-v1/{ping,status-active,cost-branch}.json`, `lifecycle-v3/{status-running,status-terminal,process-terminal-v1}.json`, `persisted-0.71-dialect/{foreground,async-launch,bg-wait,workflow}.jsonl`; provenance manifest with commit/version and **synthetic safe** bounded values. Contract tests: fixture -> L0 adapter -> canonical AgentRun -> report and privacy scan; unknown versions/extra fields/missing artifacts.

## 10. WebSocket-ready target architecture

```
 Pi JSONL / published safe refs     pi-subagents in-process RPC + event hints
        |                                        |
 L0 persisted dialect adapter          L0 live capability adapter
        \                                      /
         \-- exact-key, field-aware L1 reconcile --/
                     | native + child separate
              canonical session/report DTO
                     |            |
               HTTP snapshots     WebSocket: reportChanged(revision,scope)
                     \            /
                    same server-side report builder
```

Raw RPC over WebSocket is rejected (privacy/version/coupling); canonical AgentRun deltas need field-level out-of-order merges and duplicate replay in browser; **invalidation + HTTP refetch** reuses current DTO and makes transport replaceable. Only emit changed revision after a bounded canonical rebuild; coalesce/debounce and per-session scope; refresh failure sends nothing or explicit unavailable rather than a fabricated delta. Trigger candidates: producer `child-status`/`async-complete` (hints only), Inspector WAL write/maintenance completion, current session write/agent settled, targeted RPC status change, successful report revision check. Pi does not guarantee a public all-session append notification (`I:docs/research/pi-ecosystem.md` baseline); use a bounded session-owned refresh/revision mechanism, not globally scanned directories or event-as-truth. Authentication/local-only constraints from `I:docs/architecture/adr/0018-ephemeral-localhost-ui-and-immutable-snapshots.md` apply to HTTP *and* WebSocket.

**Surface parity:** Current UI/TUI may have provisional live run state only while owner process runs; history/JSON/static/global receive identical *persisted terminal facts* through the same canonical builder, within each surface's declared scope and range. History tree vs current active ancestry and date filters can legitimately differ. Define per-report `agentEvidence`/health coverage: `persisted-complete` for a proven published subset (not all possible async children), `partial-live` for provisional overlay, `partial-artifact` if linked lifecycle data missing/expired, `unsupported` for unrecognized producer contract, `unavailable` if no attributable evidence. Existing `AgentRunEffortCoverage` is field-specific and must not claim complete entire-session run inventory. Add explicit **inventory completeness/omitted** marker only when producer supplies a reliable inventory; absent producer inventory means “known runs only,” not “zero missing.” Global reports may aggregate counts of *known* terminal child runs without asserting an exhaustive fleet. Static/JSON and Session History opened at the same persisted snapshot must agree on these terminal rows; ephemeral overlays may differ with visible coverage explanation. The 4+2 target is provable only when both async root/child identities are explicitly published; do not invent parallel child identities.

## 11. Minimal DTO changes

Add **one optional `AgentRun.executionKind`** (`foreground | async | detached`), only from an explicit validated source; absent=unavailable. Workflow and nested are orthogonal topology, represented via exact parent/orchestration proof rather than mutually exclusive execution kinds; if needed later, add a separate narrow topology field, not five overlapping enum values. Change UI parent verdict for absent `parentId` from `none` to `unavailable`; reserve “primary-session child” for an explicit proven relationship (existing `evidenceToolId` proves publication in parent Pi, **not** a unique AgentRun parent). Keep opaque IDs and existing effort/usage coverage. Do not add raw producer IDs, artifact paths or producer RPC `total`.

## 12. Proposed ADR draft (not accepted; do not commit as ADR yet)

> # ADR (proposed): pi-subagents observability contract and reconciliation boundary
>
> **Status:** Proposed; pending producer contract verification and migration PR.
>
> ## Context
>
> Inspector derives native tool activity and child AgentRuns by reading Pi tool-result details. `src/integrations/subagents.ts` reconstructs producer-specific statuses, usage, workflow identity and replacements. pi-subagents now provides versioned process-local RPC, snapshot/cost capabilities and lifecycle artifacts, but RPC cost reconstructs from the current Pi branch and temporary metadata, and status does not provide an exhaustive permanent typed child ledger. Duplicate reconstruction is fragile; WebSocket transport must not introduce a second model. Existing ADRs 0002, 0007, 0009, 0010, 0011, 0016 and 0021 remain in force.
>
> ## Decision
>
> Parent Pi JSONL is the durable source for native accounting and published child facts. An L0 persisted pi-subagents dialect adapter reads supported `details.results[]`, `details.completions[]`, async launch identities, and only explicitly published, validated session-owned artifact references. An independent L0 live adapter negotiates protocol v1 with `ping`, verifies owner session and capability/schema versions, and accepts bounded typed provisional state only. Fleet keys, rendered status text, raw events, private metadata and global temp searches are excluded. RPC `cost` is a read-only separate combined-accounting check and may enrich a child field only if exact identity and the field's true presence are independently established; never import zero-filled unknown values. Unsupported future semantic contracts fall back to supported persisted evidence, or report unsupported, without heuristics. Unknown additive fields within a supported version are ignored.
>
> L1 owns exact-key aliases, same-surface replacement, field-level provenance and conflict resolution; L0 never exposes raw paths, producer IDs, task/output/error text or payloads. Use producer child `runId` only with a proven child semantic; foreground `(container runId,index)` and workflow `(root runId,workflowKey)` are scoped fallbacks. Identity remains session-scoped opaque `subagent-<digest>`. Persisted terminal facts outrank stale live running facts; equal-strength conflicts become unavailable plus a closed diagnostic, not latest-wins guesses. A disappearance of RPC cannot erase persisted facts. Missing child parts, costs, topology and proofs remain unavailable/partial; no synthetic zero. Execution kind is orthogonal to parent relationship. Native Pi usage stays the session billing total; child usage is a non-additive breakdown. Producer parent+child `total` is a distinct lower-bound view, not a replacement.
>
> Status/proof/artifact reads require exact published reference, session ownership, version, size, symlink and path validation; a new durable lifecycle reader requires a spec amendment and proof of history/cleanup behavior. The current producer's replay, result and temp status files do **not** establish indefinite terminal history. To guarantee that, first negotiate producer-published, session-persisted, versioned per-child terminal facts or an explicitly retained Inspector-owned sanitized session projection with a documented lifecycle. No child session-content replay. L0 emits only validated facts, L1 reconciles, L2 projects the same report to every surface. WebSocket emits authenticated, local-only canonical-report invalidation; HTTP remains snapshot authority. Events merely schedule refresh.
>
> ## Consequences
>
> Existing persisted parsing stays until equivalent durable evidence is proven; current and history retain separate ephemeral-vs-persisted coverage. Redundant live reconciliation and eventually much producer-specific parser code can disappear after contract fixtures and parity gates. Coupling moves to explicit protocol/lifecycle dialects and sanitized fixtures, an opt-in compatibility check and fallback tests. Unknown producer releases can disable live enrichment without disabling native reports. Static/history cannot promise full unwaited async metrics after producer cleanup until durable publication is agreed. No change to parent cost totals or raw-data privacy rules.
>
> ## Rejected alternatives
>
> Keep every parser and add RPC beside it: divergent rows, duplicate usage and greater maintenance. RPC-only: loses historical/restart/cleanup evidence and field-presence semantics. Scan arbitrary producer temp roots: violates session ownership, locality and bounds. Consume implementation-private registries or package SemVer ranges as schema: unversioned drift silently breaks meaning. Parse terminal output or pipe producer DTOs to browser: unsafe, unstable and leaks data. Persist raw status/events/results in Inspector WAL: violates privacy and retention contracts.
