# Independent design review: PR C2 lifecycle enrichment

**Verdict: REJECTED / NEEDS MORE EVIDENCE as proposed.** This is a review, not an implementation or amendment to product policy. The `details.asyncDir/status.json` reference and exact C1 `runId` bridge are legitimate for the *pinned source*, but C2 cannot activate a mutable current-session consumer while ADR 0022's same-session `ping` prerequisite remains unqualified. In addition, a pending step's `model` is a launch-resolution value, not proof of the model actually used. A narrower design is conditionally viable once the gates below are resolved. Neither lifecycle file nor its deletion may become historical authority.

Evidence baseline: Inspector `7bb79c0b5301257906d08577f9fc49175e649d76` (merged C1, PR #50; PR B #49 at `ccbada4`); producer source at immutable `nicobailon/pi-subagents@6f16d586bef814d74b3a2683cf297450ebfccb09`, whose `package.json` says `0.71.0`. The registry's `pi-subagents@0.71.0` metadata instead reports `gitHead: 4af5e85a427b9f87334585ae8d0eb365d4dd2a1e`; this review **does not** claim that installing the npm version installs the requested commit. Citations to producer paths below all refer to the immutable SHA unless noted. Investigation (`docs/research/pi-subagents-lifecycle-enrichment-investigation.md`) was read in full and treated as a hypothesis, not proof.

## 1. Independently verified facts

1. Producer `docs/observability.md:181-201,224-228` explicitly documents `status.json` inside the async run directory and says a top-level async result's `details.asyncDir` points to *that* directory. `src/runs/background/async-execution.ts:2127-2141,2222-2230` writes the versioned single-run status and returns `mode`, `runId`, `asyncId`, `asyncDir`, and empty `results`. No run-ID-derived path or directory scan is needed. `src/shared/types.ts` declares `Details.asyncDir?` and `SUBAGENT_LIFECYCLE_ARTIFACT_VERSION = 3`. The producer docs recommend ignoring additive unknown fields, not accepting an unknown/missing lifecycle version.
2. `src/shared/types.ts` declares `AsyncStatus.runId`, `mode`, `state`, `startedAt`, optional `sessionId`, optional `steps`, optional totals and optional `processTerminal`. Step `model`, `requestedModel`, `toolCount`, `turnCount`, `durationMs`, `tokens` and `totalCost` are optional. `src/runs/background/async-status.ts:360-374` serializes optional step model/count only when defined/present; the initial pending step in `async-execution.ts:2139` has no `toolCount`. `src/runs/background/subagent-runner.ts:2994,3002` increments tool counts from absent with `?? 0`, so absence cannot be converted to observed zero by the reader.
3. **Model qualification missed by investigation:** `async-execution.ts:1832-1848` creates `model` from `primaryModel` and thinking suffix; `:1882-1893` separately computes `selectedModel` through `resolveModelSelection`; `:2031-2036` passes `selectedModel` to the runner, but `:2139` writes the earlier `model` to the pending status step. These values can differ. Later `subagent-runner.ts:3760-3763,4179-4182,4659-4662` writes `singleResult.model` to the settled step. `requestedModel` is documented launch intent, not effective usage (`docs/observability.md:228`). Even the settled model is a producer-reported step model, not independently measured provider usage.
4. Producer `process-terminal.ts:133-152,225` overlays `processTerminal` in `status.json` without replacing root `state`; proof of runner exit is not proof of `WaitCompletion.success`. `docs/observability.md:197-201` describes result-file deletion and temporary replay. `async-retention.ts:14,768+` has a 30-day cleanup horizon with protection/eligibility checks, not a status-file retention guarantee; `async-job-tracker.ts:795-803` restores queued/running jobs. A persisted Pi result survives artifact deletion; a temp status does not acquire durability by surviving for a while.
5. C1 `src/integrations/subagents.ts:474-493` validates successful matching `subagent` call/result, `mode: single`, empty `results`, bounded equal `runId`/`asyncId`. `:245-418,506-755` creates an unknown/unparented launch observation and exact launch/completion aliases only for equal validated raw run IDs; private identities/public IDs are session-scoped opaque digests. It does not read `asyncDir`. `src/core/subagent-reconciliation.ts:197-219,221-253,311-346` uses later valid observation order for mutable fields, preserves terminal-status conflict rules, selects rather than sums. `src/ui/load-current.ts:100-103` accepts an injected current reader; `src/index.ts:965-1058` routes history through the canonical contribution path.
6. **C1 surface qualification missed by investigation:** outer `WaitCompletion` in producer `src/shared/types.ts::WaitCompletion` has `runId`, state/success, agent, results and archive reference, **not** an outer model or progress/tool count. In Inspector `collectRuns` the completion `pushRun(..., "disabled", ...)` does not read effort (`src/integrations/subagents.ts:607-634,812-858`). A supported outer C1 completion therefore cannot currently supersede launch `toolCalls` with a persisted count; its nested children are different run identities. A future valid persisted field should still win, but do not create a test claiming current completions provide one.
7. **Existing history-path defect, not C2 evidence:** `src/integrations/adapters/subagents.ts:55-70` returns `aliases`, but `src/index.ts:1036-1058::readSubagentContribution` copies observations/activity/diagnostics and omits `contribution.aliases`; `readHistorySessionEvidence` supplies that result to `src/ui/load-history.ts:457-461`. Thus the production history-provider path can lose C1's exact launch/completion alias even though the direct reader and C1 unit test (`tests/unit/subagents.test.ts:220-263`) preserve it. C2 must not paper over or worsen this unrelated C1 regression; establish the baseline in a separate focused fix/test if confirmed end-to-end.

## 2. Findings by severity

### BLOCKER

- **B1 — unresolved ADR 0022 activation rule.** ADR 0022, Decision/Consequences: “any future live consumer must validate `ping` for the same Pi session before activating a capability” and “only the recognized RPC protocol v1 contract is eligible for future live enrichment.” Reading a mutable `status.json` for a current report plausibly is live consumption. Calling it “persisted-reference enrichment” does **not** by itself exempt it. The proposal explicitly bans RPC. Before implementation, either (a) obtain an explicit recorded ADR decision that a validated persisted tool-result reference permits *file-only, current-view, v3* enrichment without RPC capability activation, preserving the RPC rule for RPC consumers, or (b) do not ship C2 under this scope. Do not silently ping or reclassify at implementation time. ADR 0002/spec §12's persisted-cooperative-fact boundary must also be reconciled for ephemeral current-only projections. Owner: architecture decision, outside this review.
- **B2 — pending-model overclaim.** Investigation §5/§6/§10 approves `steps[0].model` on any one-step status as actual/current `AgentRun.model`. The producer writes a pending pre-selection `model` which may differ from runner `selectedModel`; this can fabricate a model-used fact. Correct by requiring a producer-settled single step (`complete`/`failed`/`partial`/`paused`/`stopped`) whose `model` is the post-result projection, and describing the value only as producer-reported step model. If that narrower meaning is not acceptable for the public `AgentRun.model`, **defer model entirely**. `running`/`pending` model must not be reported as executed model.

### SHOULD FIX BEFORE IMPLEMENTATION

- **S1 — release provenance.** Commit declares 0.71.0, but npm 0.71.0's `gitHead` differs. Check the deployed/fixture producer's documented path and selected fields against its exact tarball/commit, or scope compatibility to a proven fingerprint/source. A bare package-version check is not a proof of this source. Unknown artifacts must fail closed (no enrichment), not mark C1 runs unsupported.
- **S2 — preserve real C1 historical identity.** Verify and separately correct the history-provider alias omission above before claiming C2 preserves *merged C1* history. Do not fold generic parser cleanup into C2. Add a current/history end-to-end assertion with both launch and completion under the default production reader, not only direct `readSubagentEvidence`/manual alias injection.
- **S3 — ambiguity and filesystem gate.** Same bounded raw launch ID can appear in multiple validated launch publications with conflicting `asyncDir` values. Refuse lifecycle enrichment for that identity rather than choose first/last path; repeated identical reference can be treated as one. Resolve path safety explicitly: an absolute, length-bounded directory from validated same result; exactly `status.json`; no raw path in diagnostics; reject non-regular/oversize files and file symlinks, no-follow on open, handle-size/re-read check, bounded read, swallowed errors. The existing archive reader's final-file `O_NOFOLLOW` alone does **not** prevent symlink traversal in parent path components. If promising “no directory symlinks,” check each component or use an equivalent safe directory-constrained opening method; otherwise narrow the promise and document residual same-user path substitution. Neither a guessed temp root nor raw run ID is a containment substitute.
- **S4 — test real precedence, not hypothetical persisted data.** A terminal C1 completion supplies status/success, but not outer model/toolCalls. Test that lifecycle `running`/`failed` and process proof do not change persisted terminal status, and that future *valid* persisted field observations, if any, win by order. Do not inject unsupported outer completion effort/model and call it producer evidence.

### OPTIONAL / DEFER

- A dedicated `requestedModel`, turn-count, process-exit or `status` DTO, generic live-source engine, new identity domain, lifecycle diagnostics, polling, and historical lifecycle fields are unnecessary. Duration needs an explicit change to ADR 0021 first. Root/step tokens and costs need a producer accounting/presence contract, not further heuristics. No new dependencies justified. Avoid requiring a new status reader module if one small bounded helper next to the existing archive reader can satisfy the trust boundary.

## 3. Field-by-field decision

| Producer v3 path | Presence / authority | C2 decision |
| --- | --- | --- |
| `lifecycleArtifactVersion`, root `mode`, root `runId`, optional `sessionId` | Version exactly `3`; `mode` exactly `single`; run ID exact with validated launch; if `sessionId` is present it must match the current Pi session. These are gates, not report fields. | **Approve as validation only**; missing version, malformed/wrong identity or wrong mode skips all enrichment. |
| `steps[0].model` | Optional. Pending value is pre-selection; settled step reports `singleResult.model`. A model string can be valid while no provider call was made. | **Conditional:** only settled one-step status, bounded/redacted label, fill absent existing model; no “measured/used provider” claim. Defer if public semantics require that. |
| `steps[0].toolCount` | Optional per-step counter. Initial pending status omits it; producer increments on tool events. Missing != 0. An explicit bounded integer 0 is distinguishable, but no reader-side default is permitted. | **Conditional approval** for current-view `AgentRun.toolCalls`, one-step shape, 0 accepted only when explicitly present and valid; coverage `partial`. Provisional, not historical/final claim. Do not use root aggregate `toolCount`. |
| Root `state`, step `status`, `processTerminal` | Mutable status/process proof, potentially stale; only step status can gate model, never become run status. | **Do not publish**; persisted terminal completion wins regardless of status conflict. |
| `startedAt`, `endedAt`, `lastUpdate`, step `durationMs` | Timestamps ≠ persisted duration; ADR 0021 expressly excludes duration from live status. | **Reject C2**; never replace `observedAt` or derive duration. |
| `steps[].requestedModel`, `turnCount` | Intent and turns are not effective model or native generations. | **Defer/reject**, no new public fields. |
| Root/step `totalTokens`, `tokens`, `totalCost`, input/output, cache/reasoning | Optional container; present numeric components have no per-component unknown flag; root may aggregate nested work, costs may be unpriced/partial. | **Reject C2** for `AgentRun.usage`, native totals and billing. No missing-to-zero conversion, no additive rollup. |
| `error`, task/goal, output, nested children, session paths, artifacts/events/replay | Sensitive, unbounded, or operational, not C2 source. | **Reject**; no raw forwarding or diagnostics. |

No `AgentRun` public DTO additions. `effortCoverage.tools` changes from `unavailable` to `partial` **only** for an explicitly observed valid step count; `0` remains valid measured snapshot, absence remains unavailable. Existing current report model/tool count may vary as mutable evidence changes or disappears; historical report fields and native/child totals must not vary with artifact retention. If “historical completeness” means completed past runs within *current* view must remain byte-stable after file deletion, exclude lifecycle even there: ephemeral enrichment cannot guarantee that property without creating a second durable authority.

## 4. Reference and identity verdict

**Reference: approved conditionally for this SHA only.** Persisted successful C1 single-run launch `details.asyncDir` → fixed documented filename `status.json`; never derive directory from ID, parse rendered text, scan roots, or look at sibling files. `asyncDir` is locator, not identity. It may be absent without affecting launch row. Validate bounded path and filesystem as S3.

**Identity bridge: approved.** Same persisted tool result passes C1's exact call/result and `runId === asyncId` validation; status root `runId` must equal that private launch run ID (and optional parent `sessionId` match); reuse existing C1 async observation's `sourceIdentity`, `order`, and `run.id`, plus existing exact C1 aliases. Status cannot establish a new row, parent, alias, order, public ID, or integration presence. Do not correlate by directory basename, public digest, agent label, timestamp, or step position. `steps.length === 1` is only a shape/cardinality check after root identity and mode have been proved; do not use it to correlate multiple runs.

## 5. Precedence verdict

**Persisted Pi > provisional lifecycle, per field.** Build persisted C1 observations first. Overlay only missing permitted fields on the *already-proven launch observation*, keep publication order/source identity, and run ordinary L1 reconciliation. Never emit a separate status observation with synthetic timestamp/order. Persisted terminal `bg_wait`/supported `subagent_wait` status/success/failure remains terminal even if lifecycle says `running`, `failed`, or process exit observed. `processTerminal` proves only process closure. No field sum, no forceful zero, no downgrade on missing/deleted file. Current C1 does not publish outer completion model/tool count; precedence is a forward-safe rule, not evidence that it already does.

## 6. Privacy and history verdict

A bounded parser should retain only version, exact ID comparison, optional session-ID comparison, mode, one step's allowed fields and (for model gating) its closed status token. Discard the rest immediately. Use existing `boundedProducerLabel` and numeric caps. No producer path/raw ID, JSON, errors, output, task or session file enters WAL/report/debug. Filesystem exceptions are swallowed; C1 persisted evidence remains intact. Archive-style read cap (128 KiB) is reasonable but not a size guarantee from producer. Unknown version/malformed/oversize/not-a-file/missing/stale/removed data is *no enrichment*, never a failed Pi tool/report or a fabricated zero. No retries/listeners; changing path target between checks must fail closed as far as platform permits.

**History is never fed lifecycle status.** History/global may still follow existing published archive-presence references; that existing C1 behavior is distinct and must not be widened to v3 data. Current snapshots may show optional provisional model/count while a file exists; no artifact-dependent totals, IDs, run count, status, parentage, historical coverage or completeness claim. Do not claim immutable current-view projections across artifact changes. The history alias omission noted in S2 makes a separate baseline check necessary.

## 7. Scope and complexity audit

Conditional C2 is structurally smaller than PR B and C1: one allowlisted bounded reader and one current-only wiring/observation decoration, plus focused sanitized tests and an explicit architecture decision. Expected production touches: `src/integrations/subagents.ts` for exact launch/reference association and same-observation decoration; a small `src/integrations/subagent-lifecycle.ts` **only if** keeping bounded file IO separate is clearer than extending `subagent-archive.ts`; `src/index.ts` for current-only reader injection. Existing `src/ui/load-current.ts`/`src/ui/bundle.ts` already expose the injection seam; `src/integrations/adapters/subagents.ts` and history contribution must remain persisted-only. No change expected in `src/core/events.ts`, `src/core/subagent-reconciliation.ts`, report DTO/projections or native accounting. Separately repairing S2, if approved, is *not* C2 scope.

Prohibited additions: AgentRun discovery from lifecycle files, directory scans, runtime RPC/ping as an implicit workaround, polling/listeners, child Pi session replay, replay/results archives as history, parent inference, generalized adapter hooks that also affect history, generic reconciliation/identity layers, parser cleanup, WebSockets or transport changes.

## 8. Corrected minimal design (conditional, not approval to implement)

1. Record explicit ADR 0022 interpretation/exemption **before** any mutable file read. If ping is required, stop rather than violating the no-RPC C2 boundary. Verify source equivalence for the actual deployed producer, not the npm string alone.
2. In the current reader only, collect eligible C1 launch observations and the `asyncDir` from their same validated persisted result. If references for one identity conflict, omit that identity's lifecycle enrichment. Preserve base evidence in all cases.
3. Read only the documented fixed `status.json` using a bounded fail-closed file operation. Check exact v3 envelope, run ID and optional session ID; require `mode: single`, `steps` length exactly 1. Validate only approved numeric/model fields. No state projection. For `model` require a settled step as in B2; for `toolCount` accept explicit bounded integers including 0 but never default absent values.
4. Add valid missing fields to the existing async launch observation only. Do not overwrite a persisted field. Preserve `sourceIdentity`, order, ID, status, parent, aliases and coverage except `tools: partial` when count is present. Allow L1's existing per-field order selection to handle any future valid persisted publication. Never persist the lifecycle projection independently.
5. Keep current/history boundary explicit at injection site; all artifact errors produce the original C1 evidence and no path-bearing diagnostic.

**If settled model cannot be distinguished safely, ship tool count only or no C2.** No second authority, no speculative fallback.

## 9. Implementation gates and test categories

- Architecture: explicit ADR 0022 decision on file-only persisted-reference enrichment vs same-session RPC ping; ADR 0021 remains unchanged because duration excluded. Clarify current-only non-durable field semantics and selected deployed producer pin.
- Contract: positive test with *sanitized* validated launch `asyncDir`, matching exact v3 status and one step; confirm same ID, unknown parent, one row. Test pending pre-selection `model` vs settled `singleResult.model` (or defer model). Test explicit `toolCount: 0`, missing count, invalid/huge/negative/fractional count, label redaction and one-step/cardinality failure.
- Fail closed: missing/vanished path, malformed/oversize JSON, non-absolute/long path, file and directory symlinks, non-regular file, unknown/missing version, wrong root mode/run ID/present session ID, additive unknown fields, conflicting duplicate launch references. No exception, new row, alias, status change or raw diagnostic.
- Precedence: persisted terminal vs stale running/failed/proof-observed status; no unsupported outer completion model/tool count asserted as producer fact; legitimate future repeated persisted field wins; native and child usage byte-identical with/without lifecycle.
- History: default production history/global reader makes **zero lifecycle reads**, even with existing file; deletion does not change history totals, identity or availability; separately validate/fix C1 history aliases (S2). Current view remains best-effort and does not claim historical completeness. Privacy scanner checks sensitive sentinels and raw IDs/paths absent from report/WAL/debug.
- Verification for eventual PR: focused tests, full tests, typecheck, lint, format checks; `npm pack --dry-run` if packaging changes. No test/production/spec/ADR edits were made in this review.

**Answer to central question:** Yes, a validated, current-only, optional v3 file can add a *provisional explicitly present field* to an already-proven C1 run without becoming a second historical authority. As written, the proposed design has not cleared ADR activation or pending-model semantics and therefore must not be implemented unchanged.
