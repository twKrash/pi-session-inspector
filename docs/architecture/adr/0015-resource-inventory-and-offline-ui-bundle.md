# ADR 0015: resource inventory, presence model, offline UI bundle, and subagent discovery

**Status:** accepted.

## Context

Three gaps remained after M7. Commands and Skills tabs were permanently `Unavailable` because Inspector had no inventory path. Integration rows could not say whether a producer was installed, merely whether evidence happened to appear. pi-subagents rich runs required a hand-made `--subagents-artifact` file, and no pinned producer ever wrote its `{version:1, runs:[{id,parentId,…}]}` shape. And the `ui` mode needed a complete, offline Inspector document rather than separate current/history/global exports.

## Decision

**Sanitized resource inventory.** Commands, skills, and a generic source inventory are read once per current-session report load from `pi.getCommands()` and `pi.getAllTools()`, deduplicated by `(name, source)`. Only `name` and `sourceInfo` are read from tools; `description`, `parameters`, and `promptGuidelines` are instruction/content text and are never read, persisted, or rendered. `sourceInfo.path`/`baseDir` are dropped at the adapter boundary. Command rows keep a bounded `name` (≤64 bytes), `source` (`extension|prompt|skill`), a normalized `sourceLabel` (`local`/`auto`/`builtin`/`sdk`, `npm:<name>` with the version dropped, else `other`), `scope`, `origin`, and an optional bounded description (single line, ≤120 bytes, not secret-like or path-like). Rows are capped at 256 commands, 128 skills, and 64 resource-source groups; skills are the `source === "skill"` subset with the `skill:` prefix stripped.

**Inventory is not invocation and not activity.** The generic `(sourceLabel, scope, origin)` groups report loaded/available resources only. Pi does not persist slash-command invocations, so commands carry no invocation counter and Inspector never infers one. Tool source attribution (`tools[].source`) is the label of that tool name in the current inventory; it is `absent` when the name is unknown, and is never inferred from prefixes or persisted.

**Persisted snapshot and refresh.** At tracking promotion Inspector writes `sessions/<sessionId>/inventory.json` (`schemaVersion: 1`, mode `0o600`, ≤64 KiB, atomic rename). Missing or unreadable snapshots are `unavailable`, never an empty list. Refresh triggers are: (1) session start after tracking promotion; (2) a `resources_discover` event with `reason === "reload"`; (3) any current-session report load (`ui`, `tui current`/`ledger`, `json current`), where Inspector re-reads `getCommands()` + `getAllTools()`, hashes the just-observed sanitized row set, and compares it with the persisted snapshot; history/global exports of other sessions do not re-read the producer. Every refresh hash-compares the bounded sanitized set against the persisted snapshot, rewriting only when the hash changes, so repeated observations of an unchanged resource set write nothing. A current-session report load keeps the in-memory observed snapshot (`presence`, the live-counter skill allowlist, and report injection) in sync with the refreshed one; a failed producer read keeps the last readable snapshot and never fabricates an empty inventory. Dynamic runtime registrations (an extension registering agents/commands after start, a late-connecting MCP server) are therefore captured at the next current-session report load at the latest; Inspector never polls, watches the filesystem, or writes Pi session data. `inventory.json` expires with the 14-day cutoff, but inventory counts survive in `aggregates.resourceCounts` and per-skill invocation counts in `aggregates.skillInvocations`.

**`presence` versus `state`.** Every known integration key gets a row. `presence` is a bounded, evidence-based signal: native inventory name matches (for example command `ponytail`, tool names `ctx_*`, `subagent*`, `lens_*`/`lsp_*`/`ast_grep`), a live or durable `permissions:ready` sighting, or the existence of evidence itself (a row with supported counters or adapter evidence is `present`). It is `absent` only when the inventory is available and the defined signal is missing, and `unknown` otherwise — a renamed or unobservable producer degrades to `unknown`, never a false `absent`. `state` is `supported` (producer evidence observed and parsed, or folded from durable evidence), `unavailable` (producer may be present but produced no observable evidence), or `unsupported` (evidence exists but its shape/version is not supported). Presence never implies activity; state never implies installation.

**Single offline `ui` bundle.** `ui` emits one self-contained document with Current, History, and Global and the existing in-page navigation. Both current views are precomputed at generation time (active-leaf and tree scope) from the same reducer/live-evidence path as `tui`/`json current`; `--scope` selects only the initially displayed view, and in-page scope switching swaps the two precomputed DTOs with no host call, re-replay, or browser-side fold. Range presets filter only the bounded embedded rows (per-view daily rows capped at 366; history adds bounded per-session summaries). A section or view that fails becomes `availability: "unavailable"` with a bounded diagnostic code while the rest still renders; rows past a cap are marked truncated. The canonical browser projection of a current view is `{ availability, diagnostic?, scope, report?, evidence?, daily?, dailyTruncated? }` — report tables live only under `report.*` and the precomputed evidence rows sit in the sibling `evidence?` key, so the browser resolves exactly one path per table. The renderer never loads, replays, or re-aggregates. Output is escaped inline JSON with no network, CDN, or server, and is byte-identical for identical inputs.

**Subagent auto-discovery.** pi-subagents runs are discovered from persisted tool results, not from a manual file, in three layers: (1) native `subagent`/`subagent_wait`/`subagent_supervisor` tool activity joined to results by `toolCallId`, always shown and never added to session totals; (2) rich runs from `details.completions[]` and `details.results[]`, with unknown fields ignored and malformed rows producing no row; (3) archive references, followed only from `details.completions[]` because that is the only surface the pinned producer publishes `archivePath` on. Child-row references are deliberately not followed: the archive records the aggregate run's own `runId` while a foreground child is identified as `<aggregate>#<index>`, so validating a child reference would weaken the exact-`runId` check. A `details.results[]` row publishing `archivePath` therefore keeps `artifacts` absent, not `"missing"`. Archive validation is strictly ordered and every failure is `"missing"`: non-empty absolute string, `lstat` regular file (symlinks and FIFOs refused), size ≤128 KiB, `O_NOFOLLOW` open with size re-verified, exact-size read with stable post-read size, then JSON `version === 1` with `runId` exactly equal to the referencing run id. Only the bounded `"available" | "missing"` verdict leaves the adapter; the path, raw run id, and every archive field are discarded, and raw producer run ids are SHA-256-hashed before they enter a report.

**Removal of `--subagents-artifact`.** No pinned producer writes the invented `{version:1, runs:[{id,parentId,…}]}` shape, so the flag, its reader, and its fixture are removed rather than preserved as a false contract. The flag now produces usage help. If a genuine published artifact contract later needs a manual entry point, it re-enters with verified provenance and its own ADR. Replaying child Pi session files (`results[].sessionFile`) for native child usage stays deferred: it would add a second bounded replay cost and a second usage-precedence rule.

## Alternatives considered

- Keep `--subagents-artifact` as a compatibility escape hatch: rejected; it advertises a format no producer emits and would require weakening archive validation.
- Follow child-row archive references: rejected; it would trade the exact-runId guarantee for unverified identity.
- Replay child Pi session files now: deferred, not adopted; out of this milestone's scope and cost budget.
- Poll or filesystem-watch resource registrations: rejected; unbounded background work for observer-only evidence.
- Trust `presence` from installation heuristics: rejected; renamed/unknown producers would render a false `absent`.
- Flatten report tables onto the current view: rejected; duplication would desynchronize the TUI/HTML/JSON consumers that share one DTO.
- Load history/global lazily in the browser: rejected; offline use requires everything embedded and precomputed.

## Consequences

Commands, Skills, and Resource sources render from sanitized inventory with explicit "inventory ≠ invocations/activity" copy; Agents render without any manual flag; `ui` is one offline document with working scope and range controls. The cost is a bounded snapshot artifact, refresh-time hashing, and two precomputed current views per `ui` invocation (one extra bounded replay of the same session). Inventory rows, not invocation semantics, degrade after the 14-day cutoff; counts and per-skill totals survive. See ADR 0010 (bounded state), ADR 0011 (privacy), and ADR 0012 (retention).
