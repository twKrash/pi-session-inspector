/tmp/rc-candidate.tgz`) with no repository checkout; all four dependencies and
peers resolved. It was then loaded by the installed `pi` (`/usr/local/bin/pi`)
in RPC mode with extension discovery disabled (`-ne -e <installed
extension>`), an isolated `HOME`, and `--offline`.

| --- | --- |

| Command registration | `get_commands` returns `session-inspector` and `session-ins`, both "Open Pi Session Inspector reports"; the only other command is Pi's own `llama` |
| `json current` | writes a 4,384-byte JSON report |
| `snapshot current` | writes a 32,578-byte self-contained HTML document |

## Benchmark measurements (release mode, 10 warm / 3 cold samples, corpus v1)

Three consecutive runs on the release candidate, plus the recorded
[M7 baseline](../benchmarks/m7-baseline.md) for variance:

| Measurement | Run 1 | Run 2 | Run 3 | M7 baseline | Variance |
| --- | --- | --- | --- | --- | --- |
| 10k-record warm replay | 107.3 ms | 110.2 ms | 107.3 ms | 42.9 ms | **+2.5×** |
| Cold 100 MiB replay (107,437 records) | 1,441.7 ms | 1,478.4 ms | 1,441.7 ms | 746.6 ms | **+1.9×** |
| HTML render, 10k records | 142.8 ms | 145.1 ms | 142.8 ms | 8.7 ms | **+16×** |
| HTML size, 10k records | 7,541,970 B | 7,541,970 B | 7,541,970 B | 2,422,211 B | **+3.1×** |
| Incremental memory, 10k records | 3.48 MB | 3.48 MB | 3.48 MB | 3.32 MB | +5% |
| Checkpoint read fold, 1,000 checkpoints | 320.6 ms | 318.5 ms | 320.6 ms | 319.2 ms | unchanged |

Within-candidate variance is ≈2% run to run, so these are reproducible
measurements rather than noise. The candidate stays inside every recorded hard
target: cold 100 MiB 1,478 ms < 2,000 ms; HTML render 145 ms < 3,000 ms;
incremental memory 3.48 MB ≤ 10 MiB. The checkpoint fold and memory figures are
unchanged from the baseline, which is why the timing gaps above are treated as
code-path changes since the baseline rather than ambient machine load.

Target-SLO variances requiring a decision before publication:

1. **HTML size, 10k records: 7.54 MB against a recorded `< 5 MiB` target.**
   This exceeds the target, which was set when the snapshot carried fewer
   sections. Hard gates are disabled until two accepted baselines exist, so it
   is not automatically blocking; the decision is either to accept this
   candidate as the second baseline with the target revised deliberately, or to
   triage the document size first.
2. **Warm replay, cold replay and HTML render times rose against the M7
   baseline** while staying inside their targets. Same decision: accept as the
   new baseline reference, or investigate before qualifying.

Not measurable in this harness (unchanged from the M7 record): 10k delta
reconcile, global fold over 1,000 checkpoints, observer scheduling, startup
p95, and current-TUI warm paint.

## Not yet run (manual, owned by the release owner)

- Final browser/TUI/privacy matrix on a real desktop session: `ui` in a browser,
  theme toggle, range/scope switching, snapshot opened from `file://`, API
  failure display, and the no-double-count refresh observation. The automated
  subsets that were run are listed above (token boundary, offline HTML, no
  external requests, determinism).
- The explicit **WSL2** case (Pi inside WSL2, Windows host browser opening the
  tokenized URL, token/Host/Origin protections intact, no unintended
  non-loopback exposure). This cannot be executed in the qualification
  environment.
- Current-TUI warm paint against its `< 150 ms` SLO (needs a TUI host).
- Supported-Pi review, migration review and accepted-risk sign-off belong to M8.

## Accepted risks, deferred work, rejected decisions

- **Accepted for now:** the HTML-size and timing variances above, pending the
  decision named with them. No unresolved Critical/Important security, privacy,
  data-loss, contract or deterministic-output finding was identified during
  this qualification.
- **Engine matrix:** qualified on Node `v22.22.1` only; `engines` requires
  `>=22.19.0` and no older major was exercised.
- **Registry state:** npm holds only `0.1.0`; no version between it and `1.0.0`
  was ever published, which the `1.0.0` CHANGELOG entry states.
- **Deferred (post-1.0, not release gates):** MCP semantic integration, skill
  invocation evidence, and Pi native telemetry integration, as recorded in the
  roadmap's post-1.0 section.
- **Rejected prototypes kept out of the artifact:** manual subagent artifact
  input (`--subagents-artifact`, replaced by auto-discovery from persisted tool
  results), timestamp-guessed subagent parentage, telemetry-derived usage
  accounting, and any presentation-only heuristic promoted to canonical
  evidence.
- **Tooling:** `publint` and `knip` remain dev-only tooling; neither ships in
  the tarball.
